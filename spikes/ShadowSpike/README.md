# ShadowSpike

Консольная утилита фазы 0. Запускается в вашем домене и проверяет допущения, которые нельзя проверить без настоящего Active Directory: вход в LDAP, список компьютеров, сессии WTS, диагностику через CIM и главный риск проекта — запуск `mstsc /shadow` под учётными данными netonly.

Утилита ничего не меняет в каталоге (операции записи не включены). Единственное действие с побочным эффектом — запуск `mstsc.exe` на шаге 9, и только после вашего подтверждения.

## Что нужно

- Windows 10/11 или Windows Server.
- .NET 10 SDK (для `dotnet run`) либо собранный `ShadowSpike.exe` (рядом должны лежать его dll).
- Сетевой доступ до контроллера домена и до проверяемых компьютеров. Порты: 389 (LDAP), 88 (Kerberos), 53 (DNS), 135 и 445 (RPC/SMB, сессии WTS), 3389 (RDP), 5985 (WinRM, диагностика) и динамические порты RDP для shadow.
- Учётная запись с правом читать каталог и с правами локального администратора на проверяемом компьютере (для сессий WTS, shadow и CIM).
- Для шага 9: запущенная или запускаемая по требованию служба «Вторичный вход в систему» (`seclogon`) и установленный `mstsc.exe`.
- Права администратора на самом компьютере не нужны.

## Запуск

Пароль не передаётся в аргументах. Утилита спросит его в консоли без эха либо возьмёт из переменной окружения `SPIKE_PASSWORD`.

### Доменный компьютер, текущий пользователь

```powershell
dotnet run --project spikes/ShadowSpike -- --domain corp.local --current-user --host pc-acc-014.corp.local
```

### Доменный компьютер, другая учётная запись

```powershell
dotnet run --project spikes/ShadowSpike -- --domain corp.local --user adm-ivanov --host pc-acc-014.corp.local
```

### Недоменный компьютер

DNS должен разрешать имена домена: DNS-сервер указывает на контроллер домена или поднят VPN. Подключаться нужно по полному DNS-имени, не по IP.

```powershell
dotnet run --project spikes/ShadowSpike -- --domain corp.local --dc dc01.corp.local --user adm-ivanov --host pc-acc-014.corp.local
```

### Полная проверка с shadow

```powershell
ShadowSpike.exe --domain corp.local --user adm-ivanov `
  --host pc-acc-014.corp.local `
  --offline-host pc-off-001 --closed-port-host pc-nofw-002 `
  --shadow-session 2 --rdp --report spike-report.md
```

Номер сессии для `--shadow-session` подсказывает шаг 6: он печатает сессии хоста и предлагает активную.

## Параметры

| Параметр | Назначение |
|---|---|
| `--domain` | DNS-имя домена. Обязателен вне домена |
| `--dc` | Контроллер домена (FQDN). Без него — автопоиск через DNS SRV |
| `--user` | Логин: `adm-ivanov`, `CORP\adm-ivanov` или `adm-ivanov@corp.local` |
| `--current-user` | Войти текущим пользователем Windows (Kerberos) |
| `--host` | Компьютер для шагов 6–9 (лучше FQDN) |
| `--offline-host` | Выключенный компьютер: ждём Unreachable/Timeout и замеряем время |
| `--closed-port-host` | Включённый компьютер с закрытым портом 445 |
| `--shadow-session` | Номер сессии для shadow (шаг 9a) |
| `--rdp` | Проверить обычный RDP тем же способом (шаг 9b) |
| `--no-consent` | Добавить `/noConsentPrompt` (нужна политика Shadow = 2 или 4) |
| `--find-user` | Строка поиска пользователей, по умолчанию `a` |
| `--report` | Файл отчёта, по умолчанию `spike-report-<дата>.md` в текущей папке |

## Шаги

1. Окружение: домен, пользователь, версия Windows, служба seclogon, Credential Guard, политика передачи учётных данных.
2. Вход (`IDomainLogonService`): учётная запись, контроллер, вид аутентификации, привилегированность.
3. DNS SRV контроллеров (через `nslookup`) и разрешение имени домена.
4. Компьютеры: количество, время загрузки, отключённые, частичное обновление за сутки, корень OU.
5. Пользователи: поиск и флаги Enabled/LockedOut/PasswordExpires.
6. Сессии WTS: `--host`, `--offline-host`, `--closed-port-host` со временем ответа.
7. Порты 135, 445, 3389, 5985.
8. Диагностика CIM: политика Shadow, брандмауэр, TermService, WinRM, вердикт.
9. `mstsc` (только с `--shadow-session` или `--rdp`): утилита покажет команду, спросит подтверждение (y/n), запустит mstsc и задаст вопросы: спросило ли окно пароль, подключился ли shadow, увидел ли пользователь запрос согласия.

Шаги, которым не хватает параметров или входа в домен, отмечаются SKIP. Исключения ловятся, утилита не падает.

## Результат

В консоль выводится таблица шагов (PASS / FAIL / SKIP, время в мс). Рядом сохраняется отчёт Markdown: окружение, таблица, подробности по шагам и раздел «Что делать, если…» (shadow не берёт netonly, seclogon остановлена, DNS не разрешается, закрыт 445, политика Shadow не равна 2 или 4). Пункты, которые сработали в вашем запуске, помечены «СРАБОТАЛО».

Код возврата: 0 — FAIL нет, 1 — есть FAIL, 2 — ошибка аргументов, 3 — не записан отчёт.

## Безопасность

- Пароль хранится только в памяти процесса и передаётся только в `LogonRequest`. В аргументы, журнал и отчёт он не попадает; из текста отчёта и консоли дополнительно вычищается.
- Переменная `SPIKE_PASSWORD` остаётся в окружении сеанса консоли: после работы очистите её (`Remove-Item Env:SPIKE_PASSWORD`).
- Отчёт содержит имена компьютеров, пользователей и учётной записи. Перед отправкой посмотрите его.
- Не запускайте утилиту подряд с неверным паролем: учётная запись может заблокироваться.
