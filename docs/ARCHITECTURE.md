# Архитектура RemoteShadow

RemoteShadow — настольная программа «пульт админа» для Windows-домена: shadow-подключение к сессиям пользователей, RDP/SSH, управление AD и диагностика в одном окне. **Только Windows.**

Главные требования к архитектуре:

1. **Новую функцию добавляют, не трогая остальной код** — одним классом или одним скриптом.
2. **Программа работает и на доменном, и на недоменном компьютере.** Если компьютер не в домене или нужна другая учётная запись, программа спрашивает домен, логин и пароль и выполняет все сетевые операции от её имени.
3. **Код, который ходит в сеть и в Windows API, отделён от интерфейса**, чтобы интерфейс можно было разрабатывать и показывать в демо-режиме без домена, а логику — тестировать без окон.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Язык и платформа | C# / .NET 10 (LTS), `net10.0-windows` | Нативный доступ к Windows API, один `.exe` |
| Интерфейс | WPF с темой Fluent + MVVM (CommunityToolkit.Mvvm) | Зрелый, собирается в один `.exe` без дополнительного рантайма, выглядит как Windows 11. WinUI 3 не взяли: без MSIX он тянет Windows App SDK и плохо собирается в single-file |
| Внедрение зависимостей | Microsoft.Extensions.DependencyInjection | Модули регистрируют свои сервисы и действия |
| Работа с AD | System.DirectoryServices.Protocols (`LdapConnection`) | Явно управляем подписью и шифрованием, постраничным поиском и таймаутами. Одинаково работает от текущего пользователя и с явными учётными данными. Сброс пароля (`unicodePwd`) — только по шифрованному каналу |
| Объявления Win32 API | Microsoft.Windows.CsWin32 | Генерирует P/Invoke-сигнатуры (WTS, LogonUser, CreateProcessWithLogonW, Credential Manager) из метаданных Windows, без ручных объявлений |
| Сессии | WTS API (`wtsapi32.dll`) | То же, что `qwinsta`/`quser`, но быстро и без парсинга текста |
| Удалённые проверки | CIM через WinRM (Microsoft.Management.Infrastructure) | Реестр, службы и брандмауэр целевого компьютера без службы Remote Registry, которая на клиентах по умолчанию выключена |
| Shadow / RDP | `mstsc.exe` | Shadow умеет только mstsc (см. [исследование](research/)) |
| SSH | `ssh.exe` в Windows Terminal или в обычной консоли | Встроенный OpenSSH-клиент Windows |
| Секреты | Диспетчер учётных данных Windows (`CredWrite`/`CredRead`) | Шифрование DPAPI, привязано к учётной записи Windows |
| Тесты | xUnit | |
| Сборка | GitHub Actions на `windows-latest` | `.exe` single-file, self-contained, **без trimming** (он ломает COM и рефлексию WPF) |

## Проекты в решении

```
RemoteShadow.sln
├─ src/
│  ├─ RemoteShadow.Core          # Контракты и модели. Без WPF и без Win32
│  ├─ RemoteShadow.Windows       # Реализации: WTS, LDAP, LogonUser, mstsc, CIM
│  ├─ RemoteShadow.Demo          # Фейковые реализации с тестовыми данными
│  ├─ RemoteShadow.Modules       # Встроенные функции: каждая — отдельный модуль
│  └─ RemoteShadow.App           # WPF-оболочка: окна, навигация, диалоги, вход
├─ spikes/
│  └─ ShadowSpike                # Консольный прототип фазы 0, в релиз не входит
└─ tests/
   ├─ RemoteShadow.Core.Tests
   └─ RemoteShadow.Integration   # Запускаются вручную на тестовом стенде
```

Правило зависимостей: `App → Modules → Core ← Windows / Demo`. Модули знают только интерфейсы из Core, поэтому один и тот же модуль работает и с настоящим доменом, и в демо-режиме.

## Интерфейс

Одно главное окно в три колонки:

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ RemoteShadow   [Компьютер, пользователь, фамилия  Ctrl+K]   CORP\adm-ivanov ▾  │
├──────────────┬────────────────────────────────────────┬────────────────────────┤
│ Компьютеры   │ ▾ corp.local    ● PC-ACC-014 Петрова А.│ PC-ACC-014  ● в сети   │
│ Пользователи │   ▾ Офис        ● PC-ACC-015 —         │ Win 11 · Бухгалтерия   │
│ Избранное    │     Бухгалтерия ○ PC-ACC-016 не в сети │ [RDP] [SSH] [C$] [⋯]   │
│ Журнал       │     Склад       ● PC-ACC-017 Сидоров П.│ Сессии                 │
│ Диагностика  │   ▸ Серверы                            │ 1 Петрова А. · активна │
│ Настройки    │                                        │  [Shadow: просмотр]    │
│              │                                        │  [Shadow: управление]  │
│              │                                        │  ☐ без запроса         │
│              │                                        │  Сообщение · Выйти     │
├──────────────┴────────────────────────────────────────┴────────────────────────┤
│ CORP\adm-ivanov · DC01.corp.local · Kerberos · в сети 182 из 230 · 10:42       │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **Слева** — страницы. Их список собирается из модулей.
- **Сверху** — общий поиск: компьютер по имени, пользователь по фамилии или логину. Результат «пользователь → компьютер → сессия» с подключением в один клик.
- **В центре** — список объектов выбранной страницы. У компьютеров слева дерево подразделений.
- **Справа** — карточка выбранного объекта и его действия, сгруппированные по `Group`. Те же действия — в контекстном меню строки. У компьютера ниже — список сессий с действиями для каждой.
- **Снизу** — строка состояния: от чьего имени работаем, какой контроллер домена, Kerberos или NTLM, сколько компьютеров в сети.
- Выделили несколько строк — справа остаются только действия, которые поддерживают пачку, с числом целей в подписи кнопки.

## Расширяемость: модули, действия, страницы

Каждая функция программы — **модуль**. Модуль регистрирует то, что он добавляет:

- **Действия (actions)** — кнопки и пункты контекстного меню для объекта: компьютера, сессии или пользователя. Например, «Shadow: управление», «Сбросить пароль», «Перезагрузить».
- **Страницы (pages)** — целые разделы в навигации. Например, «Компьютеры», «Пользователи», «Журнал».
- **Сервисы** — всё, что нужно модулю внутри.

Оболочка сама собирает все действия и показывает их в нужном месте. Добавить функцию = добавить класс; правка интерфейса не нужна.

```csharp
// Core: контракты
public interface IModule
{
    string Id { get; }
    void Register(IServiceCollection services);
}

public interface IAction<TTarget>
{
    string Id { get; }
    string Title { get; }              // «Shadow: управление»
    string Group { get; }              // «Подключение», «Сессия», «AD» — группировка кнопок
    string? Icon { get; }
    ActionDanger Danger { get; }       // None, Confirm, ConfirmWithReason
    bool SupportsBulk { get; }         // можно ли выполнить для нескольких целей сразу
    bool CanExecute(TTarget target, ActionContext context);
    Task<ActionResult> ExecuteAsync(TTarget target, ActionContext context, CancellationToken ct);
}

public sealed record ActionResult(ActionStatus Status, string? Message = null);  // Ok, Failed, Cancelled

// Цели действий
public sealed record ComputerTarget(ComputerInfo Computer);
public sealed record SessionTarget(ComputerInfo Computer, SessionInfo Session);
public sealed record UserTarget(UserInfo User);
```

`ActionContext` даёт действию всё нужное: текущее подключение к домену (`IDomainConnection`), диалоги (`IDialogService`), запуск внешних программ (`IProcessLauncher`), уведомления и `AuditDetails` — чтобы добавить подробности в запись журнала.

Оболочка берёт на себя общее для всех действий:

- **Подтверждение.** `Confirm` — диалог «Да/Нет» с перечнем целей; `ConfirmWithReason` — ещё и поле «Причина», которое попадает в журнал.
- **Журнал.** Каждый запуск записывается автоматически: кто, что, над чем, результат, ошибка. Действию не нужно помнить об аудите.
- **Пачки.** Если `SupportsBulk`, оболочка вызывает `ExecuteAsync` для каждой цели с ограничением параллельности, показывает прогресс и итог «7 из 8 успешно».
- **Ошибки.** `Failed` и исключения показываются одинаково, с текстом из `Message`.

### Пример: как добавить новую функцию

Задача: кнопка «Открыть C$» для компьютера.

```csharp
public sealed class OpenAdminShareAction : IAction<ComputerTarget>
{
    public string Id => "computer.open-admin-share";
    public string Title => "Открыть C$";
    public string Group => "Файлы";
    public string? Icon => "folder";
    public ActionDanger Danger => ActionDanger.None;
    public bool SupportsBulk => false;

    public bool CanExecute(ComputerTarget t, ActionContext ctx) => t.Computer.IsOnline;

    public async Task<ActionResult> ExecuteAsync(ComputerTarget t, ActionContext ctx, CancellationToken ct)
    {
        await ctx.Launcher.StartAsync("explorer.exe", [$@"\\{t.Computer.DnsName}\C$"], ct);
        return ActionResult.Ok();
    }
}

// регистрация в модуле
services.AddAction<ComputerTarget, OpenAdminShareAction>();
```

Кнопка появится в карточке компьютера и в контекстном меню автоматически, а запуск попадёт в журнал.

### Уровни расширения (по мере роста)

1. **Встроенные модули** (с первой версии) — классы в `RemoteShadow.Modules`.
2. **Скрипт-действия** (фаза 9) — папка `scripts/` рядом с `.exe`. Каждый `.ps1` с заголовком-метаданными (название, цель, группа, опасное ли) становится кнопкой без перекомпиляции. Программа передаёт в скрипт имя компьютера, ID сессии или логин пользователя. Скрипты запускаются только если подписаны (AllSigned) или папка доступна на запись только администраторам: иначе любой, кто может туда писать, выполняет код с правами админа.
3. **Плагины-DLL** (позже) — сборки из папки `plugins/`, которые загружаются через `AssemblyLoadContext` и регистрируют свои `IModule`.

## Подключение к домену и учётные данные

### Какую учётную запись использовать

Рекомендуется отдельная учётная запись с **делегированными правами**: управление пользователями в нужных OU и локальный администратор на рабочих станциях через GPO. Учётная запись Domain Admins для этой работы не нужна, и вводить её пароль на недоменном ноутбуке опасно.

### Два режима

| Режим | Когда | Как работает |
|---|---|---|
| **Текущий пользователь** | Компьютер в домене, и вы вошли учётной записью с нужными правами | Всё через Kerberos от вашего имени, пароль не нужен |
| **Явные учётные данные** | Компьютер не в домене, или вы вошли обычной учётной записью, а админская — отдельная | Окно входа: домен, контроллер домена (необязательно), логин, пароль |

При запуске программа проверяет, состоит ли компьютер в домене (`NetGetJoinInformation`). Если нет — сразу показывает окно входа. Если да — показывает то же окно, где по умолчанию выбран текущий пользователь, а одним кликом можно ввести другую учётную запись. Режим запоминается. Сменить учётную запись можно в любой момент в правом верхнем углу.

### Окно входа

- **Домен** — например `corp.local`. Контроллер домена находится автоматически через DNS (`_ldap._tcp.dc._msdcs.<домен>`), но его можно указать вручную.
- **Логин** — `CORP\adm-ivanov` или `adm-ivanov@corp.local`.
- **Пароль.**
- **Запомнить** — логин сохраняется всегда, пароль только по отдельной галочке, в Диспетчере учётных данных Windows. Если учётная запись входит в привилегированные группы (Domain Admins, Enterprise Admins, Administrators), галочка «запомнить пароль» недоступна, а программа показывает предупреждение.
- Перед входом программа проверяет учётные данные пробным подключением к LDAP и сразу говорит, что не так: неверный пароль, учётная запись заблокирована, контроллер домена недоступен, DNS не разрешает домен.

### Как учётные данные применяются

Все сетевые операции идут через одну абстракцию `IDomainConnection`, поэтому модули не знают, в каком режиме работает программа.

| Операция | Текущий пользователь | Явные учётные данные |
|---|---|---|
| LDAP (поиск, сброс пароля, группы) | `LdapConnection`, Negotiate, подпись и шифрование | То же, с `NetworkCredential` |
| WTS (сессии), CIM, перезагрузка | Как есть | Внутри `WindowsIdentity.RunImpersonated` с токеном `LogonUser(LOGON32_LOGON_NEW_CREDENTIALS)` — аналог `runas /netonly`: локально вы — это вы, в сети — админская учётная запись |
| mstsc (shadow, RDP) | Обычный запуск | `CreateProcessWithLogonW` с флагом `LOGON_NETCREDENTIALS_ONLY`. Нужна служба «Вторичный вход в систему» (`seclogon`) |
| ssh | `ssh.exe user@host` | То же: ssh не использует сетевые учётные данные Windows |

Известные ограничения (проверяются в фазе 0):

- **Обычный RDP может спросить пароль** даже при netonly-запуске. Чтобы CredSSP пропускал без пароля, на клиенте нужна политика «Разрешить передачу учётных данных по умолчанию», а Credential Guard такую передачу запрещает совсем. Обход через `cmdkey` записывает пароль на диск, поэтому по умолчанию его не используем.
- **Shadow запускается без пароля**, если mstsc берёт сетевые учётные данные из netonly-процесса. Если нет — запасной вариант `mstsc /prompt`.

Пароль хранится в памяти только на время работы программы (защищён `CryptProtectMemory`) и никогда не пишется в журнал, файлы настроек или аргументы командной строки.

### Требования к недоменному компьютеру

- DNS должен разрешать имена домена: DNS-сервер указывает на контроллер домена, или подключён VPN с доменным DNS.
- Подключение к компьютерам — по полному DNS-имени (`dNSHostName` из AD), а не по IP: иначе Kerberos не работает и Windows откатится на NTLM, который в защищённых доменах запрещён.
- Доступны порты: 389/636 (LDAP), 88 (Kerberos), 445 (SMB/RPC — сессии и shadow), 3389 (RDP), 5985 (WinRM — диагностика), динамические порты RdpSa для shadow.
- Служба `seclogon` запущена.

## Поиск компьютеров

Все компьютеры домена хранятся в памяти, в индексе. LDAP используется только для его обновления, а поиск, фильтрация и списки подразделений работают по памяти мгновенно.

```
 AD (LDAP)  ──постраничный запрос──▶  ComputerIndex (память)  ──▶  поиск Ctrl+K, списки OU
     ▲                                   │        ▲
     └──── частичное обновление ◀────────┘        └── кэш на диске при запуске
           (whenChanged), раз в 5 мин
```

### Загрузка из AD

`LdapConnection` к контроллеру домена (автопоиск через DNS SRV), `AuthType.Negotiate`, подпись и шифрование. Один постраничный запрос по всему домену:

```csharp
var req = new SearchRequest(domainDn,
    "(&(objectCategory=computer)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))",
    SearchScope.Subtree,
    "name", "dNSHostName", "operatingSystem", "operatingSystemVersion",
    "description", "lastLogonTimestamp", "distinguishedName", "objectGUID", "whenChanged");
req.Controls.Add(new PageResultRequestControl(500));
// цикл: SendRequest → cookie из PageResultResponseControl → следующая страница
```

- Отключённые компьютеры скрыты условием по `userAccountControl`; галочка «показывать отключённые» убирает его.
- 10 000 компьютеров — несколько МБ памяти и 1–3 секунды загрузки. Страницы показываются по мере прихода.
- Ключ записи — `objectGUID`: он не меняется при переименовании и переносе в другое подразделение.

### Кэш и обновление

- Индекс сохраняется в `%LocalAppData%\RemoteShadow\cache\<домен>.json`. При запуске список сразу берётся из кэша, обновление идёт в фоне. Секретов в кэше нет.
- Раз в 5 минут — частичное обновление: тот же запрос с условием `(whenChanged>=<прошлая синхронизация − 5 мин>)` к тому же контроллеру домена (`whenChanged` не реплицируется, поэтому контроллер домена должен быть одним и тем же).
- Удалённые из AD компьютеры частичное обновление не видит, поэтому раз в час и по кнопке «Обновить» индекс загружается целиком.
- Если контроллер домена сменился (недоступен, выбран другой), следующее обновление — полное.

### Дерево подразделений

- Ветки загружаются лениво: при раскрытии — запрос `SearchScope.OneLevel` с фильтром `(|(objectClass=organizationalUnit)(objectClass=container))`.
- Компьютеры подразделения берутся из индекса по `distinguishedName`, без запроса в LDAP. Галочка «включая вложенные» переключает между прямым родителем и совпадением по суффиксу DN.

### Поиск в строке Ctrl+K

- Ищет по индексу по `name`, `description` и `dNSHostName`, без учёта регистра, с задержкой 150 мс после ввода.
- Порядок результатов: точное совпадение имени → начало имени → подстрока в имени → подстрока в описании.
- Та же строка ищет пользователей (фамилия, логин) в индексе пользователей, устроенном так же. Если в кэше сессий есть свежие данные, у пользователя сразу видно, где он залогинен.
- LDAP на каждую букву не запрашиваем: поиск по подстроке `name=*text*` в AD не использует индекс и медленный.

### Где это в коде

| Проект | Что |
|---|---|
| `RemoteShadow.Core` | `IComputerDirectory`: `IAsyncEnumerable<ComputerInfo> EnumerateAsync(DateTime? changedSince, CancellationToken ct)`, `GetOuChildrenAsync(string dn, CancellationToken ct)` |
| `RemoteShadow.Windows` | Реализация `IComputerDirectory` через `LdapConnection` |
| `RemoteShadow.Demo` | Тестовые компьютеры и подразделения |
| `RemoteShadow.Modules` | `ComputerIndex`: кэш, фоновое обновление, ранжирование результатов поиска |

Подход рассчитан на домены примерно до 50 000 компьютеров. Для больших доменов индекс ограничивается выбранными в настройках подразделениями.

## Опрос компьютеров

Опрос сотни компьютеров — самое медленное место, поэтому правила общие для всех модулей:

- **Онлайн-статус** — TCP-подключение к порту 445 с таймаутом 500 мс. ICMP не используем, он часто закрыт.
- **WTS-вызовы блокирующие и не отменяются.** Поэтому они выполняются на отдельном ограниченном пуле потоков (по умолчанию 32), а не в пуле .NET. У каждого хоста жёсткий дедлайн; если вызов не уложился, хост помечается «не отвечает», а поток дорабатывает в фоне.
- **Кэш.** Последние результаты по каждому компьютеру хранятся с временем получения; интерфейс сразу показывает кэш и обновляет его по мере ответов.
- **«Найти пользователя»** сначала ищет в кэше, затем опрашивает выбранное подразделение. Опрос всего домена — только по явной кнопке с предупреждением: массовое перечисление сессий похоже на разведку злоумышленника, и EDR или Defender for Identity может поднять тревогу.

## Демо-режим

С ключом `--demo` вместо `RemoteShadow.Windows` подключается `RemoteShadow.Demo`: тестовый домен с подразделениями, компьютерами, пользователями и сессиями. Так интерфейс можно разрабатывать без домена, а скриншоты для документации не раскрывают реальные данные.

## Журнал

Каждое действие записывается оболочкой автоматически: время, кто (админская учётная запись), что, над чем, причина (если спрашивали), результат. Shadow без запроса пользователю — отдельный тип записи.

- **Локально** — JSON Lines в `%AppData%\RemoteShadow\audit\yyyy-MM.jsonl`, виден на вкладке «Журнал». Это история для самого админа: он может её изменить, поэтому это не аудит.
- **Централизованно (по желанию)** — копия записи в общую папку из настроек, например `\\srv\audit$\RemoteShadow\`. Права на папку: админы могут только создавать файлы и дописывать, но не изменять и не удалять.
- Целевые компьютеры сами пишут события shadow в журнал `Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational` (20503, 20504, 20508).

Пароли и другие секреты в журнал не попадают никогда.

## Безопасность

- Пароль — только в памяти и, по желанию, в Диспетчере учётных данных Windows; для привилегированных учётных записей сохранение запрещено.
- Опасные действия (выход пользователя, перезагрузка, сброс пароля) требуют подтверждения; shadow без запроса пользователю и массовые действия — ещё и причины.
- Shadow без запроса пользователю работает, только если это разрешено групповой политикой `Shadow` на целевом компьютере. Программа это не обходит, а диагностика показывает текущее значение и какую политику поменять.
- Настройки, которыми управляет GPO, программа не меняет на компьютере напрямую: их перезапишет следующий `gpupdate`.
- Внешние программы запускаются со списком аргументов, без `cmd /c`, а имена компьютеров проверяются перед передачей в `mstsc` или `ssh`.
- `.exe` подписывается: неподписанную программу, которая перечисляет сессии и запускает процессы под чужой учётной записью, блокируют антивирусы.
