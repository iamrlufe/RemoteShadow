# План разработки RemoteShadow

Программа только для Windows. Порядок выбран так, чтобы сначала в реальном домене проверить главную связку — shadow и сетевые вызовы под чужой учётной записью с недоменного компьютера, — потом сделать вход в домен, минимальный каркас и только потом функции. Каждая фаза заканчивается рабочим `.exe`, который можно проверить на тестовом стенде.

Архитектура описана в [ARCHITECTURE.md](ARCHITECTURE.md), исследование — в [research/](research/).

## Фаза 1. Вход в домен

- [ ] Определение, состоит ли компьютер в домене (`NetGetJoinInformation`)
- [ ] Окно входа: «текущий пользователь» или «другая учётная запись»; домен, контроллер домена (автопоиск через DNS SRV или вручную), логин, пароль, «запомнить»
- [ ] Проверка учётных данных пробным LDAP-подключением с понятными ошибками: неверный пароль, учётная запись заблокирована, контроллер домена недоступен, DNS не разрешает домен
- [ ] Проверка привилегированных групп после входа: предупреждение и запрет сохранять пароль
- [ ] `IDomainConnection` с двумя реализациями: текущий пользователь и явные учётные данные
- [ ] Олицетворение `LogonUser(LOGON32_LOGON_NEW_CREDENTIALS)` для сетевых вызовов
- [ ] Запуск внешних программ через `CreateProcessWithLogonW(LOGON_NETCREDENTIALS_ONLY)`; понятная ошибка, если служба `seclogon` остановлена
- [ ] Сохранение логина и, по желанию, пароля в Диспетчере учётных данных Windows
- [ ] Смена учётной записи и выход из неё в правом верхнем углу

**Готово, когда:** с компьютера вне домена программа запрашивает учётные данные, проверяет их и показывает домен и учётную запись в строке состояния; на доменном компьютере можно войти и текущим пользователем, и другой учётной записью.

## Фаза 3. Компьютеры

Схема — в [архитектуре](ARCHITECTURE.md#поиск-компьютеров).

- [ ] `IComputerDirectory` в Core; реализации в Windows (`LdapConnection`) и Demo
- [ ] Загрузка всех компьютеров домена постраничным запросом (500 на страницу), отключённые скрыты, галочка «показывать отключённые»
- [ ] `ComputerIndex`: индекс в памяти с ключом `objectGUID`, кэш на диске `%LocalAppData%\RemoteShadow\cache\<домен>.json`
- [ ] Фоновое обновление: частичное по `whenChanged` раз в 5 минут, полное раз в час, при смене контроллера домена и по кнопке «Обновить»
- [ ] Дерево подразделений (OU) с ленивой загрузкой веток; компьютеры подразделения — из индекса, галочка «включая вложенные»
- [ ] Список компьютеров: имя, ОС, описание, OU, последний вход (с пометкой «приблизительно»: `lastLogonTimestamp` отстаёт на 9–14 дней), статус онлайн
- [ ] Поиск Ctrl+K по индексу: имя, описание, DNS-имя; ранжирование «точное → начало → подстрока имени → описание»
- [x] Онлайн-статус: TCP-подключение к 445 с таймаутом 500 мс, не больше 64 одновременно, только видимые строки и выбранное подразделение, кэш на 2 минуты, обновление UI пачкой раз в 200 мс — реализовано (`OnlineStatusService`) и расширено сверх исходного пункта: отдельный `IComputerAvailabilityService` добавляет ICMP/RDP/SMB/SSH с настраиваемыми портами/таймаутами/параллелизмом и статусами Online/Offline/Checking/Unknown; см. `AGENT_HANDOFF.md`, «Этап 5»
- [x] Избранные компьютеры — есть (`AppSettings.FavoriteComputers`), плюс пользовательские группы компьютеров (`ComputerGroups`, см. «Этап 5»); «недавние подключения» — поле `RecentComputers` заведено в настройках, но отдельно не проверялось в этой сессии
- [ ] Тесты `ComputerIndex` на демо-данных: ранжирование, частичное обновление, переименование и перенос компьютера — не проверялось отдельно в этой сессии (вероятно покрыто существующими тестами `RemoteShadow.Infrastructure.Tests`, не подтверждено явно)

**Готово, когда:** видно все компьютеры домена по подразделениям и понятно, какие сейчас включены; повторный запуск показывает список из кэша меньше чем за секунду, а поиск по 10 000 компьютерам отвечает быстрее 50 мс.

## Фаза 4. Сессии и подключения (главная функция)

- [ ] Список сессий выбранного компьютера через WTS API: ID, пользователь, состояние, время простоя, время входа, клиент
- [ ] WTS-вызовы на отдельном ограниченном пуле потоков с дедлайном на хост
- [ ] Действия сессии: **Shadow: просмотр**, **Shadow: управление**, галочка «без запроса пользователю» (с причиной в журнале)
- [ ] Сессии, к которым shadow невозможен (отключена, заблокирована), помечены ещё до клика
- [ ] Действия компьютера: **RDP**, **SSH** (`ssh user@host` в Windows Terminal, иначе в обычной консоли)
- [ ] **«Найти пользователя»**: сначала кэш, затем опрос выбранного подразделения с выводом результатов по мере ответов; опрос всего домена — по отдельной кнопке с предупреждением про EDR
- [ ] Понятные ошибки shadow: политика запрещает, нужен запрос пользователю, нет прав, порты закрыты, служба `TermService` остановлена

**Готово, когда:** админ находит пользователя по фамилии и за два клика подключается к его сессии.

## Фаза 5. Пользователи AD

- [ ] Поиск пользователей: ФИО, логин, отдел, телефон, включён ли, заблокирован ли, срок пароля, последний вход
- [ ] Сбросить пароль (сгенерировать или ввести, «сменить при следующем входе») — только по шифрованному каналу
- [ ] Разблокировать, включить и отключить учётную запись
- [ ] Просмотр групп пользователя; добавить в группу и удалить из группы
- [ ] Переход «пользователь → где он сейчас залогинен» (связь с фазой 4)

**Готово, когда:** сброс пароля, разблокировка и изменение групп работают с делегированной учётной записью, а при нехватке прав программа говорит, каких именно.

## Фаза 7. Диагностика

- [ ] Проверка компьютера: DNS, порты 135/445/3389/5985, служба `TermService`
- [ ] Чтение политики `Shadow` и правила брандмауэра «Remote Desktop - Shadow» через CIM/WinRM; если WinRM недоступен — «не удалось проверить»
- [ ] Отчёт «почему не работает shadow» с подсказками, что исправить
- [ ] Кнопка «Исправить» только для того, что не управляется GPO (например, запустить `TermService`), с подтверждением и записью в журнал. Для настроек из GPO — указание, какую политику поменять

**Готово, когда:** на стенде для каждой из типовых причин (политика, брандмауэр, служба, нет прав) отчёт называет причину и способ исправить.

## Риски и что проверить в домене первым делом

| Риск | Что делаем |
|---|---|
| `mstsc /shadow`, запущенный с сетевыми учётными данными (`LOGON_NETCREDENTIALS_ONLY`) с компьютера вне домена, не подхватывает их | Проверяем в фазе 0 до любого интерфейса; запасной вариант — `mstsc /prompt` |
| Обычный RDP спрашивает пароль из-за Credential Guard или политики передачи учётных данных | Проверяем в фазе 0; по умолчанию пароль не пишем через `cmdkey`, а показываем окно mstsc |
| Служба `seclogon` отключена hardening-политикой | Понятная ошибка и подсказка в окне входа и в диагностике |
| Компьютер вне домена не разрешает имена домена | Понятная ошибка в окне входа и подсказка про DNS/VPN |
| Опрос сотен компьютеров долгий: WTS-вызовы блокирующие и не отменяются | Проверка порта 445, отдельный пул потоков, дедлайн на хост, кэш |
| Массовый опрос сессий похож на разведку и поднимает тревогу EDR | Опрос по подразделению по умолчанию, весь домен — по отдельной кнопке с предупреждением; позже — индекс без опроса |
| Пароль Domain Admin хранится на неуправляемом ноутбуке | Рекомендуем делегированную учётную запись; для привилегированных групп сохранение пароля запрещено |
| Локальный журнал может изменить сам админ | Называем его историей; для аудита — центральная папка только на дописывание и события на целевых компьютерах |
| Правка реестра на компьютере перезаписывается GPO | Для настроек из GPO не правим, а показываем, какую политику поменять |
| Неподписанный `.exe` блокируют SmartScreen и антивирус | Подпись в фазе 8 обязательна; до этого — только тестовый стенд |
