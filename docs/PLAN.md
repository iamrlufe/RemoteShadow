# План разработки RemoteShadow

Порядок выбран так, чтобы сначала появился каркас, в который удобно добавлять функции, потом вход в домен (без него ничего не работает на недоменном компьютере), и только потом сами функции. Каждая фаза заканчивается рабочим `.exe`, который можно проверить в домене.

Архитектура описана в [ARCHITECTURE.md](ARCHITECTURE.md), исследование — в [research/](research/).

**Готово, когда:** пустое окно программы собирается в CI, а `.exe` скачивается со страницы сборки.

## Фаза 1. Каркас и расширяемость

- [ ] Интерфейсы `IModule`, `IAction<T>`, `IPage`, `ActionContext` в Core
- [ ] Реестр действий: оболочка сама строит кнопки и контекстные меню по зарегистрированным действиям, группирует по `Group`, спрашивает подтверждение для `IsDangerous`
- [ ] Главное окно: навигация слева (страницы), поиск сверху, панель деталей и действий справа, строка состояния (кто вошёл, какой домен)
- [ ] Сервисы оболочки: диалоги (подтверждение, ввод текста, ввод пароля), уведомления, запуск процессов
- [ ] Журнал аудита (JSON Lines) и вкладка «Журнал»
- [ ] Настройки (`%AppData%\RemoteShadow\settings.json`)
- [ ] Демо-режим с тестовыми данными; запуск на Mac для проверки интерфейса

**Готово, когда:** в демо-режиме видны тестовые компьютеры и пользователи, а новая кнопка добавляется одним классом (проверяется тестом и примером в документации).

## Фаза 2. Вход в домен

- [ ] Определение, состоит ли компьютер в домене (`NetGetJoinInformation`)
- [ ] Окно входа: домен, контроллер домена (автопоиск через DNS SRV или вручную), логин, пароль, «запомнить»
- [ ] Проверка учётных данных пробным LDAP-подключением с понятными ошибками: неверный пароль, учётная запись заблокирована, DC недоступен, DNS не разрешает домен
- [ ] `IDomainConnection` с двумя реализациями: текущий пользователь и явные учётные данные
- [ ] Олицетворение `LogonUser(LOGON32_LOGON_NEW_CREDENTIALS)` для сетевых вызовов (аналог `runas /netonly`)
- [ ] Запуск внешних программ через `CreateProcessWithLogonW(LOGON_NETCREDENTIALS_ONLY)`
- [ ] Сохранение логина и, по желанию, пароля в Диспетчере учётных данных Windows
- [ ] Меню «Войти под другой учётной записью» и «Выйти»

**Готово, когда:** с недоменного ноутбука программа запрашивает учётные данные, проверяет их и показывает имя домена и администратора в строке состояния.

## Фаза 3. Компьютеры

- [ ] Дерево подразделений (OU) из AD
- [ ] Список компьютеров: имя, ОС, описание, OU, последний вход, статус онлайн
- [ ] Поиск по имени и описанию
- [ ] Проверка онлайн-статуса пачкой (ping + порт 445) с ограничением параллельности и кэшем

**Готово, когда:** видно все компьютеры домена по подразделениям, и понятно, какие сейчас включены.

## Фаза 4. Сессии и подключения (главная функция)

- [ ] Список сессий выбранного компьютера через WTS API: ID, пользователь, состояние, время простоя, время входа, клиент
- [ ] Действия сессии: **Shadow: просмотр**, **Shadow: управление**, галочка «без запроса пользователю»
- [ ] Действия компьютера: **RDP**, **SSH** (в Windows Terminal, иначе в обычной консоли)
- [ ] **«Найти пользователя»**: опрос сессий онлайн-компьютеров параллельно (выбранная OU или весь домен), результат «пользователь → компьютер → сессия» с подключением в один клик
- [ ] Понятные ошибки shadow: политика запрещает, нужен запрос пользователю, нет прав, порты закрыты

**Готово, когда:** админ находит пользователя по фамилии и за два клика подключается к его сессии.

## Риски и что проверить в домене первым делом

| Риск | Что делаем |
|---|---|
| `mstsc /shadow` с сетевыми учётными данными (`LOGON_NETCREDENTIALS_ONLY`) с недоменного компьютера может вести себя иначе, чем с доменного | Проверить в фазе 2 на тестовом стенде, до UI для shadow |
| Недоменный компьютер не разрешает имена домена | Понятная ошибка в окне входа и подсказка про DNS/VPN |
| Опрос сотен компьютеров долгий из-за таймаутов RPC у выключенных машин | Сначала быстрая проверка порта 445, ограничение параллельности, кэш |
| Неподписанный `.exe` блокирует SmartScreen или антивирус | Подпись в фазе 8; до этого — «Подробнее → Выполнить в любом случае» |
| Разработка на Mac, работа на Windows | Демо-режим для интерфейса, CI на Windows для сборки, проверка в домене после каждой фазы |
